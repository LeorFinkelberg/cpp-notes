В заголовочных файлах обычно содержится следующее [[Литература#^70c8d3]]<c. 431>:
- прототипы функций,
- объявления структур,
- объявления классов,
- объявления шаблонов,
- встроенные функции.

_Объявления структур_ можно помещать в заголовочные файлы, поскольку они ==не создают переменные==, а только указывают компилятору, как создавать структурную переменную, когда она объявляется в файле исходного кода. Подобно этому _объявления шаблонов_ -- это ==не код, который нужно компилировать, а инструкции для компилятора ==указывающие, каким образом генерировать определения функций, чтобы они соответствовали вызовам функций, встречающимся в исходном коде [[Литература#^70c8d3]]<c. 431>

Пример заголовочного файла
```c++
// coordin.h
#ifndef COORDIN_H_
#define COORDIN_H_

// шаблоны структур
struct polar
{
  double distance;
  double angle;
};
struct rect
{
  double x;
  double y;
}

// прототипы
polar rect_to_polar(rect xypos);
void show_polar(polar dapos);

#endif
```
### Переменные со статической продолжительностью хранения

Язык C++, как и С, предоставляет переменные со статической продолжительностью хранения с тремя видами связывания [[Литература#^70c8d3]]<c. 442>:
- внешнее (возможность доступа в разных файлах),
- внутреннее (возможность доступа к функциям внутри одного файла),
- отсутствие связывания (возможность доступа только к одной функции или к одному блоку внутри функции).

Поскольку количество статических переменных не меняется на протяжении выполнения программы, она не нуждается в специальных механизмах, подобных стеку, чтобы управлять ими. Компилятор просто резервирует фиксированный блок памяти для хранения всех статических переменных, и эти переменные доступны программе на протяжении всего времени ее выполнения.

Более того, если статическая переменная не инициализирована явно, компилятор устанавливает ее в 0. Элементы статических массивов и структур устанавливаются в 0 по умолчанию.

Если внешняя переменная используется в нескольких файлах, только один из них может содержать _определение_ этой переменной (согласно принципу одного определения). Но во всех прочих файлах, где эта переменная используется, она должна быть объявлена с указанием ключевого слова `extern` [[Литература#^70c8d3]]<c. 445>. 

То есть `extern` это по сути ссылка на внешнюю переменную (переменную, определенную где-то в другом месте).
```c++
// program1.cpp
#include <iostream>
using namespace std;

#include "mystuff.h"

int process_status = 0; // определение переменной; компилятор под нее выделяется память

int main() {
  ...
}

// program2.cpp
#include <iostream>
using namespace std;

#include "mystuff.h"

extern int process_status; // переменная определена где-то в другом месте
...
```

Объявление `extern double warming;` означает использовать переменную `warming`, определенную где-то во внешнем файле.

Если поместить _операцию разрешения контекста_ `::` перед именем переменной, будет использоваться ==глобальная версия== этой переменной [[Литература#^70c8d3]]<c. 448>

==NB! В многофайловой программе внешнюю переменную можно определять в одном и только одном файле. Все остальные файлы, использующие эту переменную, должны содержать ее объявление с ключевым словом `extern` ==

Если статическая локальная переменная, определенна внутри блока, то она существует и если блок неактивен. Таким образом, статическая локальная переменная может сохранять свое значение между вызовами функции. Кроме того, если ==статическая локальная переменная инициализируется, это делается только один раз при запуске программы==. Последующие вызовы функции не будут приводить к повторной инициализации переменной, как это происходит в случае автоматических переменных [[Литература#^70c8d3]]<c. 451>. 

Список спецификаторов хранения:
- `auto`: исключен из спецификаторов в C++11
- `register`
- `static`
- `extern`
- `thread_local`
- `mutable`

Ключевое слова `volatile` указывает, что значение в ячейке памяти может быть изменено, даже если в коде программы нет ничего такого, что может модифицировать ее содержимое. 

С помощью спецификатора `mutable` можно указать, что отдельный член структуры (или класса) может быть изменен, даже если переменная типа структуры (или класса) объявлена со спецификатором `const`.

В C++ (но не C) модификатор `const` привносит небольшие изменения в классы хранения, используемые по умолчанию. Глобальная переменная со спецификатором `const` по умолчанию имеет внутреннее связывание. Другими словами, ==в C++ глобальное определение `const` обрабатывается так, будто в нем использован спецификатор `static`==
```c++
const int fingers = 10; // то же самое, что и static const int fingers = 10;

int main() {
  ...
}
```

Если бы глобальные объявления `const` имели внешнее связывание, как обычные переменные, это бы вызывало ошибку, поскольку нарушало бы _правило одного определения_. Однако поскольку определенные внешне данные `const` имеют внутреннее связывание, можно использовать одни и те же объявления во всех файлах [[Литература#^70c8d3]]<c. 454>

Внутреннее связывание также означает, что каждый файл получает собственный набор констант, а не разделяет их с другими файлами. ==Каждое определение является приватным для файла, который его содержит== Именно поэтому определения констант целесообразно поместить в заголовочный файл. Таким образом, если включить один и тот же зголовочный файл в два файла исходного кода, они оба получат один и тот же набор констант.
### Функции и связывание

Язык С++, как и С, не позволяет объявлять одну функцию внутри другой, поэтому все функции автоматически получают статическую продолжительность хранения, то есть существуют во время выполнения программы. ==По умолчанию функции имеют внешнее связывание==, в том смысле, что _могут разделяться между файлами_ [[Литература#^70c8d3]]<c. 455>

На самом деле в прототипе функции можно указать ключевое слово `extern`, отразив, что эта функция определена в другом файле, но это не обязательно. (Чтобы программа могла найти функцию в другом файле, этот файл должен быть одним из тех, который компилируется как часть программы, или библиотечным файлом, поиск которого осуществляет компоновщик) Можно также ограничить область видимости функции одним файлом, назначив для нее ==внутреннее связывание== с помощью ключевого слова `static`. Это ключевое слово должно применяться и к прототипу, и к определению функции
```c++
static int private(double x);
...
static int private(double x) {
  ...
}
```

В результате функция известна только в пределах данного файла. Это также означает, что то же самое имя можно назначить какой-то другой функции в другом файле. Как и в случае с переменными, статическая функция переопределяет внешнее определение для файла, содержащего статическое объявление. Таким образом, файл, содержащий определение статической функции, будет использовать именно эту версию функции даже при наличии внешнего объявления функции с таким же именем [[Литература#^70c8d3]]<c. 455>

Предположим, что производится вызов функции в определенном файле программы. Где компилятор С++ будет искать определение этой функции? Если прототип функции в данном файле указывает, что функция является _статической_, компилятор ищет ее определение только в этом файле. В противном случае компилятор (а также компановщик) просматривает все файлы программы. Если компилятор находит два определения, он выдает сообщение об ошибке, поскольку может существовать только одно определение внешней функции. Если компилятору не удается обнаружить ни одного определения этой функции, он переходит к поиску в библиотеках. Отсюда вывод: если вы определите функцию с тем же именем, что и в библиотечной функции, компилятор будет использовать вашу версию функции, а не библиотечную [[Литература#^70c8d3]]<c. 456>

Может случится, что операция `new` не сможет найти запрошенный объем памяти. Раньше в C++ такая ситуация обрабатывалась возвратом нулевого указателя из операции `new`. Но сейчас `new` генерирует исключение `std::bad_alloc` [[Литература#^70c8d3]]<c. 458>.
### Операция `new` с размещением

Обычно операция `new` отвечает за поиск _в куче_ блока памяти, который имеет достаточный размер, чтобы удовлетворить запрос памяти. _Операция `new` с размещением_ позволяет указать адрес используемого блока. Нужно включить заголовочный файл `new`, который содержит прототип этой версии `new`
```c++
include <new>

struct chaff {
  char dross[20];
  int slag;
}

char buffer1[50];
char buffer2[500];

int main() {
  chaff *p1, *p2;
  int *p3, *p4;
  
  p1 = new chaff; // помещает структуру в кучу
  p3 = new int[20]; // помещает массив int в кучу
  
  // Две формы операции new с размещением
  p2 = new (buffer1) chaff; // помещает структуру в область buffer1
  p4 = new (buffer2) int[20]; // помещает массив int в область buffer2
  ...
}
```
### Пространства имен

Пространства имен могут находится на глобальном уровне или внутри других пространств имен, однако они не могут быть помещены в блок. Пространства имен являются _открытыми_. Это означает, что можно добавлять новые имена в существующие пространства имен
```c++
namespace Jack {
  double pail; // объявление переменной
  void fetch(); // прототип функции
  int pal; // объявление переменной
  struct Well { ... }; // объявление структуры
}

namespace Jill {
  double bucket(double n) { ... } // определение функции
  double fetch; // объявление переменной
  int pal; // объявление переменной
  struct Hill { ... }; // объявление структуры
}

namespace Jill {
  char* goose(const char*);
}
```

Разумеется для этого необходим какой-то способ доступа к именам заданного пространства имен. Простейший способ предусматривает использование операции разрешения контекста (`::`), которая позволяет уточнить имя с помощью его пространства имен
```c++
Jack::pail = 12.34;
Jill::Hill mole;
```

В С++ предлагаются два механизма:
- объявление `using`: делает доступным отдельное имя,
- директива `using`: делает доступными все имена.

Объявление `using` добавляет в декларативную область отдельное имя
```c++
namespace Jill {
  double bucket(double n) { ... }
  double fetch;
  struct Hill { ... };
}

char fetch;

int main() {
  using Jill::fetch; // помещение fetch в локальное пространство имен 
  
  cin >> fetch; // чтение значение в переменную Jill:fetch
  cin >> ::fetch; // чтение значения в глобальную переменную
}
```

Помещение объявления `using` на внешний уровень приводит к добавлению соответствующего имени в глобальное пространство имен
```c++
void other();
namespace Jill {
  double bucket(double n) { ... }
  double fetch;
  struct Hill { ... };
}

using Jill::fetch; // помещение fetch в глобальное пространство имен

int main() {
  cin >> fetch; // чтение значения в Jill::fetch
  other();
  ...
}

void other() {
  cout << fetch; // вывод значения Jill::fetch
  ...
}
```

При размещении директивы `using` на глобальном уровне имена пространств имен становятся доступными глобально
```c++
#include <iostream> // помещает имена в пространство имен std
using namespace std; // делает имена доступными глобально
```

NB! Декларативная область -- глобальное пространство имен [[Литература#^70c8d3]]<c. 464>

NB! Предположим, что одно и то же имя определено как в пространстве имен, так и в декларативной области. При попытке применить объявление `using`, чтобы перенести имя из пространства имен в декларативную область, два имени вступят в конфликт, и отобразится сообщение об ошибке. Если с помощью директивы `using` перенести имя из пространства имен в декларативную область, локальная версия этого имени скроет версию из пространства имен [[Литература#^70c8d3]]<c. 469>

Может задать пседоним для пространства имен или вложенных пространств имен
```c++
namespace elements {
  namespace fire {
    int flame;
	...
  }
}

namespace myth {
  using Jill::fetch;
  using namespace elements;
  using std::cout;
  ...
}

namespace MEF = myth::elements::fire;
using MEF::flame;
```

Неименованные пространства имен могут служить альтернативой применению статических переменных с внутренним связыванием
```c++
static int counts; // статическая переменная, внутреннее связывание
int other();

int main() {
  ...
}

int other() {
  ...
}
```

С использованием пространств имен этот код можно переписать так
```c++
namespace {
  int counts; // статическая переменная, внутреннее связывание
}
int other();

int main() {
  ...
}

int other() {
  ...
}
```

Имена функций, объявленные в пространстве имен, имеют область видимости пространства имен, поэтому определения должны находиться в том же самом пространстве имен, что и объявления
```c++
// namesp.h
#include <string>

namespace pers {
  struct Person {
    std::string fname;
    std::string lname;
  };
  void getPerson(Person&);
  void showPerson(Person&);
}

namespace debts {
  using namespace pers;
  struct Debt {
    Person name;
    double amount;
  };
  void getDebt(Debt&);
  ...
}
```

Файл исходного кода
```c++
// namesp.cpp
#include <iostream>
#include "namesp.h"

namespace pers {
  using std::cout;
  using std::cin;
  void getPerson(Person& rp) {
    cout << "Enter first name: ";
	cin << rp.fname;
	...
  }
  
  void showPerson(const Person& rp) {
    std::cout << rp.lname << ", " << rp.fname;
  }
}

namespace debts {
  ...
}
```

Рекомендации [[Литература#^70c8d3]]<c. 475>:
- Используйте переменные в именованных пространствах имен вместо внешних глобальных переменных.
- Используйте переменные в неименованных пространствах имен вместо статических глобальных переменных.
- Используйте директиву `using` только в качестве временного средства адаптации устаревшего кода к использованию пространств имен.
- Не применяйте директивы `using` в заголовочных файлах. Порядок следования заголовочных файлов может влиять на поведение программы. Если вы используете директиву `using`, помещайте ее после всех директив препроцессора `#include`.
- Для импорта имен отдавайте предпочтение операции разрешения контекста или объявлению `using`.
- Для объявлений `using` отдавайте предпочтение локальной, а не глобальной области видимости.
